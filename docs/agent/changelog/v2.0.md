## v2.0.11 | 2026-11-25 | Stable | Fix Single-Stream 2 MiB Stop-and-Wait Stall, Unlimited Delivery Cap Clamping & ULID Cache Split
- **Scope**: `DonbyNetwork`, `DonbyUHDModule`, `DonbyApp` (`AppState+DownloadsAndCache`, `PlayerView*`, `Modules/UHD`), `DonbyCore`, `DonbyCoreTests`, `build_app.sh`, `scripts/package_dmg.sh`, `docs/agent`
- **Root Cause / Goal**: Eliminate severe 5–7 minute playback rebuffering on high-bitrate 4K streams (e.g. `33–39 Mbps` peak segments). Log and L2 chunk-arrival analysis showed two compounding causes: (1) `active_video_delivery_limit == 0` ("unlimited") was clamped via `max(1, ...)` to `1`, and (2) under `dynamicConcurrencyCap <= 1`, `spawnChunkFetchLocked` capped every Range request to `4` chunks (`2 MiB`) while `demux_worker` kept `cursorOffset` flush with the download frontier, serializing every `2 MiB` behind a ~`391ms` p50 TTFB gap (`~3.8–4.0 MiB/s` ceiling). Additionally, `e`-prefixed vs bare 26-char ULIDs split L2 cache directories across detail preload and continue-watching playback.
- **Changes**:
  - **Zero-as-Unlimited Delivery Cap (`TurboStreamingSessionHub.swift`, `UHDStreamClient+AuthAndAccount.swift`, `UHDModuleManager.swift`, `AppState+DownloadsAndCache.swift`, `UHDAccountDashboardView.swift`)**: Preserved `activeVideoDeliveryLimit == 0` as unlimited (`max(0, ...)`), clamping `turboConnectionBudget` only when `activeVideoDeliveryLimit > 0`, and displaying `"不限"` in the subscription dashboard.
  - **Single-Stream Adaptive Large-Span Range & Safe Rescue (`TurboStreamByteHandle+Scheduler.swift`, `TurboStreamByteHandle.swift`, `TurboStreamingSessionHub.swift`)**: Added `singleStreamMode` (`!inOpenProbePhase && dynamicConcurrencyCap <= 1 && index > 0`) scaling Range spans to `16 / 32 / 48` chunks (`8 / 16 / 24 MiB` by `measuredWireSpeedMBs`, capped at `min(64, prefetchAheadChunks)`) while keeping Chunk 0 cold probe at `2` chunks; expanded `dynamicConcurrencyCap == 2` warm follow-up to `8` chunks (`4 MiB`); disabled `isSlowPlayheadCrawl` concurrent rescue when `dynamicConcurrencyCap <= 1` and cancelled stalled tasks before single-stream rescue; raised `timeoutIntervalForResource` to `90s`; added rate-limited `[TurboCache]` slow-read diagnostics (`wait >= 1.0s`).
  - **Bitrate-Aware Prefetch & ULID Key Normalization (`TurboCacheAndDownloadEngine.swift`, `PlayerView+PlaybackEngine.swift`, `PlayerView.swift`)**: Normalized `[ems]01...` 27-char ULIDs in `makeAssetKey` and `cachedProgress`; added `PlayerView.resolvedTurboPrefetchChunks` for ~18s bitrate-aware prefetch horizon (`24...360`, bitrate cap `144` chunks).
- **Invariants & Pitfalls**:
  - Never clamp `activeVideoDeliveryLimit == 0` to `1`; `0` means unlimited in the UHD streaming API.
  - Under `dynamicConcurrencyCap <= 1`, never spawn a second concurrent rescue connection while the primary stream is actively receiving bytes (`isSlowPlayheadCrawl` disabled; stalled primary task cancelled before rescue).

# Changelog Shard: v2.0.x

## v2.0.24 | 2026-11-27 | Pre-release | Multi-Lane Streaming Pool, Instant-Start Parallel Prefetch & Playback-Priority Download Yielding
- **Scope**: `DonbyNetwork` (`TurboStreamingSessionHub`, `DownloadStreamingHelpers`, `TurboStreamByteHandle*`, `TurboCacheAndDownloadEngine`, `DonbyDownloadManager*`, `TieredAssetChunkStore`), `DonbyApp` (`Player/PlayerView*`, `DetailView+DataLoading`, `AppState+DownloadsAndCache`), `DonbyCore` (`AppUpdatePolicies`), `DonbyCoreTests` (`DonbyCoreTests`, `NetworkPlaybackAndDownloadTests`), `build_app.sh`, `scripts/package_dmg.sh`, `docs/agent`
- **Root Cause / Goal**: Runtime logs showed `wire=0.29-0.59 MB/s` mid-playback stalls, `1.15s` Cues cold-read waits on 64-track 4K MKVs (`chunk=18636`), and serial RTT overhead on cold resume opens because: (1) `TurboStreamingSessionHub` multiplexed all Turbo playback streams and Emby/UHD API calls onto one `URLSession` (single HTTP/2 TCP flow); (2) `startDetailPreload` used throwaway ephemeral sessions and fetched head/tail/runway serially; (3) `> 4 GiB` container tail probes prefetched only `1 MiB` and cold resume did not speculatively warm the resume anchor; (4) `DonbyDownloadManager` ran `maxConcurrentDownloads = 2` concurrently with active playback, lacked a Worker-0 302 resolution barrier (causing 6-worker origin redirect bursts), lacked cross-host `Authorization` stripping on redirects, and used mismatched 6s-vs-2.5s crawl windows.
- **Changes**:
  - **4-Lane Multi-TCP Streaming Hub & API Isolation (`TurboStreamingSessionHub.swift`, `TurboStreamByteHandle+Completion.swift`)**: Separated `DonbyNetworkSession.sharedURLSession` into an isolated `apiURLSession` and upgraded `TurboStreamingSessionHub` to 4 `ephemeral` streaming lanes (independent TCP/TLS flows with strictly serial `delegateQueue`), adding least-loaded scheduling, cross-lane rescue (`excludeLane`), per-lane stall recycling (`reportLaneStall`/`reportLaneHealthy`), cross-host `Authorization` stripping on redirects, and immediate slow-primary cancellation when a rescue attempt wins.
  - **Instant-Start Tail/Resume Prefetch & Warm-Lane Detail Preload (`TurboStreamByteHandle.swift`, `TurboStreamByteHandle+Scheduler.swift`, `TurboCacheAndDownloadEngine.swift`, `DetailView+DataLoading.swift`, `PlayerView+PlaybackEngine.swift`)**: Expanded `> 4 GiB` EOF Cues window to `2 MiB` (`4` chunks), added parallel speculative resume-anchor prefetch (`initialStartSeconds > 5`, `budget >= 3`), and upgraded `startDetailPreload` to reuse `warmStreamSession(forLane:)` with parallel Header + Cues + `4 MiB` playhead runway warm-up.
  - **Playback-Priority Download Yielding & Worker Coordination (`DonbyDownloadManager.swift`, `DownloadStreamingHelpers.swift`, `DonbyDownloadManager+WorkerAndMigration.swift`, `DonbyDownloadManager+Migration.swift`, `TieredAssetChunkStore.swift`, `AppState+DownloadsAndCache.swift`)**: Set `maxConcurrentDownloads = 1` (fairly splitting budget if raised), added nested `beginPlaybackNetworkPriority`/`endPlaybackNetworkPriority` yielding during remote playback, added Worker-0 initial 302 barrier, early redirect callback + cross-host `Authorization` stripping in `DownloadRangeStreamDelegate`, `ActiveWorkerCounter` + `3.5s` aligned crawl window, degraded-CDN re-resolution after 2 stall recycles, progress-aware retry accounting, and relaxed disk backpressure (`128`/`96`).
- **Invariants & Pitfalls**:
  - Keep `URLSession` `delegateQueue.maxConcurrentOperationCount == 1` on every streaming lane and download worker; keep `beginPlaybackNetworkPriority` paired with `endPlaybackNetworkPriority` on error/stop paths; never bypass `<= 800L` file caps (extracted `DownloadStreamingHelpers.swift`, `TurboStreamByteHandle+Completion.swift`, `DonbyDownloadManager+Migration.swift`).
- **Verification**:
  - `./scripts/dev.sh test`: Rust kernel (`8/8`), Swift `DonbyCoreTests` (`56/56` across 5 suites including `NetworkPlaybackAndDownloadTests`), and `check_agent_docs.py` (`164` owned files, `0` orphans, `0` broken links) PASS.

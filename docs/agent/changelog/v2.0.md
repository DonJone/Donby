# Changelog Shard: v2.0.x

## v2.0.2 | 2026-11-24 | Pre-release | Modularize Tier-1 Sources & Fix UHDNow Dual-Mode Artwork, Single-Episode Detail, Pagination & Watch Records
- **Scope**: `DonbyCore`, `DonbyNetwork`, `DonbyUHDModule`, `DonbyApp`, `DonbyApp/Modules/UHD`, `DonbyCoreTests`, `docs/agent`
- **Root Cause / Goal**: Decompose 7 oversized Swift files into focused <= 800-line extensions with a dedicated L1 `uhd-module.md` map, eliminate 401/404 `/emby/Items/...` artwork request storms and UHD token leaks, restore single-episode covers/logos/credits/seasons, support >100-episode seasons, persist episode metadata in watch history, and surface `next_up` in Home Continue Watching.
- **Changes**:
  - **Tier-1 Modularization**: Split `UHDStreamClient`, `DetailView`, `AppState`, `ArtworkComponents`, `EmbyClient`, `UHDAppHooks`, and `UHDModels` into cohesive feature extensions within existing SwiftPM targets; added `docs/agent/modules/uhd-module.md`.
  - **Dual-Mode Artwork (`EmbyClient+ArtworkAndFallback.swift`, `MediaArtworkViews.swift`, `DetailView+SeasonsAndEpisodes.swift`, `EmbyModels.swift`)**: Guarded `imageURL(server:itemId:)` to return `nil` when `isUHDNativeExtensionActive` is true; aligned `.primary`/`.backdrop`/`.thumb` fallback chains (`poster <-> thumb <-> backdrop`); switched episode cards to `kind: .thumb`; added `EmbyItem.withInheritedArtworkFallback` for unscraped episodes.
  - **Single-Episode Detail & Pagination (`UHDStreamClient+DetailAndMapping.swift`, `UHDAppExtensionPlugin.swift`, `DetailView+DataLoading.swift`, `UHDModuleManager.swift`)**: Mapped `logoFallback` on `mapEpisode`, added ambiguous-stub 404 retry (`episode`/`movie`/`tv`) in `fetchItemDetail`, added automatic pagination (`page_size=100`, up to 20 pages) in `fetchSeasonEpisodes`, and resolved missing `seriesId` stubs in `loadDetailPayload` before fetching credits/seasons/playback-state.
  - **Watch Records & Home `next_up` (`AppStateModels.swift`, `AppState+{WatchRecords,PlaybackLifecycle,DownloadsAndCache}.swift`, `PlayerView.swift`, `EmbyMainView.swift`)**: Persisted optional `mediaType` + `seriesId` on `WatchRecordItem`, routed `resolveSeriesName` through `DonbyMediaServiceRegistry`, and merged deduplicated `nextUpItems` into Home `继续观看`.
  - **Tests (`Package.swift`, `DonbyCoreTests.swift`)**: Added `DonbyNetwork` test dependency, `.serialized` suite isolation, `embyClientDualModeEpisodeArtworkAndUHDTokenIsolation`, and `watchRecordItemDecodesLegacyJSONAndPersistsEpisodeMetadata`.
- **Invariants & Pitfalls**:
  - Never generate `/emby/Items/...?api_key=` URLs when `isUHDNativeExtensionActive(for: server)` is true; keep `DonbyCore` and `DonbyNetwork` free of `DonbyUHDModule` imports.
- **Verification**:
  - `./scripts/dev.sh build && ./scripts/dev.sh test`: 7/7 Rust tests, 23/23 Swift tests (`0.447s`).
  - `DONBY_PURE=1 ./scripts/dev.sh build && DONBY_PURE=1 ./scripts/dev.sh test`: 7/7 Rust tests, 18/18 pure Swift tests (`0.427s`).

## v2.0.1 | 2026-11-24 | Pre-release | Extension Plugin Slot Architecture, Design Firewall & `DONBY_PURE=1` Build Switch
- **Scope**: `DonbyApp/Extensions`, `DonbyApp/Modules/UHD`, `Package.swift`, `DonbyCoreTests`, `AGENTS.md`
- **Root Cause / Goal**: Eliminate 51 scattered `#if canImport(DonbyUHDModule)` conditional blocks across core `DonbyApp` files (`PlayerView`, `ServerViews`, `AppState`, `DetailView`, `EmbyMainView`, `MainWindowView`, `SettingsView`) so core views stay 100% service-agnostic, optional extensions cannot pollute Donby's visual system, and pure core builds are continuously verifiable.
- **Changes**:
  - `Sources/DonbyApp/Extensions/DonbyAppExtension.swift`: Introduced `DonbyAppExtensionCenter` (containing the single compile-time bootstrap seam), `DonbyAppUIExtensionPlugin`, `DonbyPlayerCompanion` / `DonbyPlayerCompanionBox`, and shared cinema drawer components (`PlayerDrawerGlassCard`, `PlayerDrawerRowBackground`).
  - `Sources/DonbyApp/Modules/UHD/{UHDAppHooks,UHDModuleManager}.swift`: Consolidated UHD line/speed-test sheet (`UHDLineAndAccountSheetView`), Watch Party + GPU Danmu player companion (`UHDPlayerCompanionController`), browse/detail pagination & enrichment, and reactive `objectWillChange` forwarding behind `UHDAppExtensionPlugin`.
  - `Sources/DonbyApp/{MainWindowView,EmbyMainView,DetailView,ServerViews,AppState,PlayerView}.swift` & `Views/SettingsView.swift`: Removed all direct `DonbyUHDModule` imports and `#if canImport` branches, routing exclusively through `DonbyAppExtensionCenter` and `DonbyPlayerCompanionBox`.
  - `Package.swift` & `Tests/DonbyCoreTests/DonbyCoreTests.swift`: Added `DONBY_PURE=1` (`DONBY_PURE_BUILD`) mode omitting `DonbyUHDModule` and excluding `Sources/DonbyApp/Modules/UHD`, while keeping `keepSignedInVaultPolicyAndLegacyDecoding` active in pure builds.
  - `AGENTS.md`: Codified Extension Slot & Design System Firewall redlines.
- **Invariants & Pitfalls**:
  - Never add `#if canImport(DonbyUHDModule)` outside `DonbyAppExtensionCenter.installCompiledExtensionsIfNeeded()` and `Modules/UHD/`.
  - Extension views under `Modules/UHD/` must compose canonical Donby components (`Components/*`, `PlayerDrawerGlassCard`, `ServerLineOptionRow`) and sanitize remote API strings via `UHDDisplayNormalizer` before display.
- **Verification**:
  - `DONBY_PURE=1 ./scripts/dev.sh build && DONBY_PURE=1 ./scripts/dev.sh test`: 0 warnings, 7/7 Rust tests, 16/16 pure core Swift tests.
  - `./scripts/dev.sh build && ./scripts/dev.sh test`: 0 warnings, 7/7 Rust tests, 21/21 full Swift tests.

## v2.0.0 | 2026-11-24 | Pre-release | Zero-Dependency Rust Playback Kernel & Pure-C11 ABI Shim
- **Scope**: `KernelRust`, `DonbyKernelC`, `build_kernel.sh`, `Package.swift`, `scripts/dev.sh`, `build_app.sh`, `.github/workflows/build-dmg.yml`
- **Root Cause / Goal**: Replace the legacy 6,498-line C++20 playback engine (`dk_engine.cpp`, archived on `legacy/cpp-kernel`) with a memory-safe, zero-external-crate Rust static library (`KernelRust`) while preserving 100% C ABI binary compatibility with `donby_kernel.h` so zero Swift, Metal shader, or `TurboStreamByteHandle` files require changes.
- **Changes**:
  - `Sources/DonbyKernelC/dk_ffi_shim.c`: Pure-C11 FFmpeg/libass struct accessors with compile-time `_Static_assert` ABI size checks, `av_log` variadic bridge, PGS/DVD `0x0` `AVDISCARD_ALL` fast-probe bypass, VideoToolbox HW + `IOSurface` `CVPixelBufferPool` (`NV12`/`P010`) SW decode, HDR10 + Dolby Vision Profile 5/8 RPU polynomial/MMR `DKGpuColorUniforms` builder, `SwrContext` 5.1 center-boost + 48kHz mono VAD tap, `AudioQueue` C wrappers, and `CFStringTransform`.
  - `KernelRust/src/{abi,ffi,dovi,vad,clock,subtitle,lib}.rs`: Complete Rust playback engine with `LIVE_PLAYERS` + `ReaderGuard` UAF protection, demux/video/audio worker threads, `AudioQueue` startup/rebuffer/Pause-During-Seek serialization, `DONBY_TEST_MUTED` guard, HEVC NAL 62/63 scanners, `VadAudioRing` (60s @ 16kHz), `libass` + PGS dual-layer RGBA compositor, Pair-A Cinema Semantic Bilingual Engine, and all 37 `dk_*` C exports.
  - `build_kernel.sh`, `Package.swift`, `scripts/dev.sh`, `build_app.sh`, `.github/workflows/build-dmg.yml`: Wired zero-crate Cargo release build (`opt-level = 3`, `codegen-units = 1`, `panic = "abort"`, no `lto` to avoid Homebrew LLVM 23 vs Apple CLT bitcode mismatch) into local dev, app bundling, and CI.
- **Invariants & Pitfalls**:
  - `donby_kernel.h` (7 structs/enums, 37 functions) remains frozen; `dk_player_acquire_frame` stays strictly non-blocking on `CVDisplayLink`.
  - Do not enable `lto = "thin"` in `KernelRust/Cargo.toml` while building with Homebrew `rustc` (LLVM 23) + Apple CLT linker/tools.
- **Verification**:
  - `./scripts/dev.sh build && ./scripts/dev.sh test`: 0 warnings, 7/7 Rust unit tests, 20/20 `DonbyCoreTests`.
  - `tmp/test_pair_a.cpp`: 15/15 bilingual cases, 32/32 assertions passed (0 failures).
  - Muted end-to-end smoke + 10-bit HEVC HDR10 HW/SW suites (`DONBY_TEST_MUTED=1`): 27/27 checks passed.

## v1.4.14 | 2026-11-21 | Pre-release | Build pipeline speedup: 40x+ faster incremental Debug/Release builds, single-compile C++ kernel & incremental dylib bundling
- **Scope**: `build-release`, `kernel-cpp`
- **Root Cause / Goal**: Profiling revealed four major build bottlenecks on macOS CLT (Swift 6.4.2): (1) Swift 6.4's default `swiftbuild` engine invalidated its explicit SDK module cache on every run with `--sdk MacOSX26.5.sdk`, turning no-op Debug builds into `54s` and Release builds into `104s`; (2) Release WMO compiled `DonbyApp` single-threaded (`46s` on 1-file edits); (3) `dk_engine.cpp` was compiled twice (`build_kernel.sh` + SwiftPM `DonbyKernelC` target); (4) `build_app.sh` unconditionally regenerated `AppIcon.icns`, wiped all 28 cached dylibs in `Contents/Frameworks/`, and `release_local.sh` did not sync the verified bundle to `/Applications/Donby.app`.
- **Changes**:
  - `Package.swift`: Removed redundant `-L build_kernel -ldonby_kernel` linking and added `-O3` + `CoreGraphics` to `DonbyKernelC` so SwiftPM compiles `dk_engine.cpp` once at `-O3` (both Debug & Release) with automatic incremental caching.
  - `scripts/dev.sh`: Added unified local dev CLI (`build` / `test` / `app` / `release`) auto-selecting CLT SDK, feature-detecting `--build-system native`, and sharing CLT `Testing.framework` flags between `build` and `test` so switching between them never invalidates `.build`.
  - `build_app.sh`: Removed redundant `./build_kernel.sh` step; enabled `--build-system native` (feature-detected for CI compatibility) and multi-core incremental `-O` (`-no-whole-module-optimization -incremental`, opt-in `DONBY_WMO=1`); skipped `generate_icon.swift` when `AppIcon.icns` is up to date; preserved `Contents/Frameworks/` across in-place installs and replaced `--deep` signing with top-level signing + strict `--deep --strict` verification.
  - `scripts/bundle_dylibs.py`: Batched `install_name_tool` flags per binary, cached & recursively validated all transitive `@rpath` dylibs in `Contents/Frameworks/`, pruned stale dylibs, and parallelized fresh dylib signing with `ThreadPoolExecutor`.
  - `build_kernel.sh`: Added mtime up-to-date check (`0.03s` skip; pass `--force` to override).
  - `scripts/package_dmg.sh` & `scripts/release_local.sh`: Added in-place `/Applications/Donby.app` sync (`SYNC_INSTALLED_APP=1`, default on in `release_local.sh`, disable with `--no-install`) eliminating redundant second builds after release packaging.
  - `.github/workflows/build-dmg.yml`: Removed redundant `./build_kernel.sh` CI step.
  - Bumped all 3 version sources (`build_app.sh`, `DonbyAppInfo.fallbackVersion`, `docs/agent/INDEX.md`) + `scripts/package_dmg.sh` + `DonbyCoreTests` to `1.4.14`; synced `AGENTS.md`, `INDEX.md`, `build-release.md`, `kernel-cpp.md`.
- **Invariants & Pitfalls**: `scripts/bundle_dylibs.py` must recursively enqueue cached `@rpath/` transitive dependencies into `queue` so multi-hop libraries (e.g. `libpcre2-8`, `libintl`, `libbrotlicommon`) are never pruned. Always keep `codesign --verify --deep --strict` and external-Homebrew `otool -L` closure checks active.
- **Verification**: `./scripts/dev.sh build` dropped `54.1s -> 1.29s` (no-op `0.22s`); `./scripts/dev.sh test` dropped `28.5s -> 0.88s` (8/8 passed); incremental `./build_app.sh` dropped `~110s -> 5.0s` (`1.58s` Release `-O` compile + 28/28 cached dylibs verified); `./build_kernel.sh` up-to-date skip `0.03s`; Pre-release `v1.4.14` (with automatic in-place `/Applications/Donby.app` sync) passed.

## v1.4.11 | 2026-11-21 | Pre-release | Native-consensus / English-preferred dual-subtitle anchor, ±260ms anti-flicker snap & dash-less speaker rescue

- **Root Cause / Goal**: In real-world dual-track playback (e.g. CN + EN streaming SRTs), two subtle issues remained: (1) 100–250ms timestamp offsets between tracks caused staggered double-flashing on cue entrance/exit; (2) official simplified Chinese SRTs frequently omit `- ` speaker dashes and concatenate two speakers with spaces (`你确定吗 相信我`), while English tracks (which serve as the global master template for both English-native and JP/KR/EU titles) preserve explicit `- ` dialogue turns.

  - `Sources/DonbyKernelC/include/donby_kernel.h`: Added `dual_anchor_mode` (`0 = auto/English-preferred`, `1 = primary`, `2 = secondary`) to `DKSubtitleStyleConfig`.
  - `Sources/DonbyApp/PlayerView.swift`: Added weighted consensus `resolvedDualAnchorMode()` combining `OriginalTitle` Unicode script analysis (immune to dubbed remux audio track 0) and active/default non-dub audio language: Native Chinese media selects Chinese as anchor; English-native and third-language (JP/KR/EU) media select English as anchor; re-applies on audio track switches.
  - `Sources/DonbyKernelC/dk_engine.cpp`:
    - Added **Dual-Track Anti-Flicker Timestamp Snap (`±260ms`)** in `dk_try_render_paired_bilingual_locked`: snaps overlapping non-anchor cue start/end edges to the active anchor window and suppresses `<=260ms` leading/trailing overhangs tied to an adjacent anchor cue (while preserving standalone non-anchor cues with no anchor overlap).
    - Added `dk_try_split_counterpart_by_anchor_ratio` in `dk_build_paired_turns`: when the anchor track explicitly marks a 2-speaker turn with `- ` dashes (speaker order `1 -> 2` is invariant across languages), rescues a dash-less 1-line counterpart via Tier 1 sentence-ending punctuation (`？`/`！`/`。`/`…`) or Tier 2 ratio-matched spaces/commas, pairing into `CN1+EN1 / CN2+EN2` while avoiding mis-splitting unmarked single-speaker inverted clauses.
  - Bumped all 6 version locations to `1.4.11` and synced `docs/agent/INDEX.md`, `kernel-cpp.md`, `app-player-ui.md`.
- **Invariants & Pitfalls**: Never ratio-split single-speaker unmarked cues (prevents EN<->CN clause-order inversion); never suppress standalone non-anchor cues that do not overlap any anchor event.
